Fleet Management System - Project Summary and Detailed Description
=================================================================

1) Project Summary
------------------
A modular, production-ready Python Fleet Management System that loads vehicle telemetry from CSV, validates it, models vehicles using OOP, computes fleet-level statistics (averages), and generates safety alerts. The project emphasizes readability (PEP 8), robustness, testability, and performance. It centralizes configuration, separates I/O from business logic, includes comprehensive unit/integration tests, and provides an optional concurrency simulation for real-time updates using threads.

2) Architecture (Modules and Roles)
-----------------------------------
- vehicle.py: Defines the Vehicle class with attributes (id, speed, temperature, fuel) and strict input validation; includes __str__ and __repr__.
- fleet_manager.py: Defines FleetManager to manage vehicles, compute averages, produce alerts (temperature > threshold, fuel < threshold), and print summaries.
- main.py: CLI entrypoint; loads CSV, orchestrates FleetManager, prints summary, averages, and alerts. Retains a compatibility shim for the loader function.
- io_utils.py: CSV loading utilities (load_vehicles_from_csv); logs/continues on malformed rows; raises on missing file.
- config.py: Centralized constants for validation bounds (speed/temp/fuel ranges) and alert thresholds (overheat, low fuel).
- tests.py: Comprehensive unittest suite covering validation, averages, alerts, CSV handling, and CLI behavior.
- concurrency.py: Optional module simulating real-time telemetry updates using threading; thread-safe reads and updates; benchmarks single-threaded vs multi-threaded runs.
- vehicles.csv: Sample dataset for quick testing and demonstration.
- README.md: Complete developer documentation (overview, usage, testing, thresholds, edge cases, and extension guidance).

3) Key Functionalities
----------------------
- Data Ingestion: Robust CSV parsing; malformed rows are logged and skipped without crashing; missing file raises FileNotFoundError.
- Validation: Vehicle constructor validates id (non-empty) and coerces/validates speed, temperature, fuel to safe ranges.
- Statistics: Accurate averages for speed, temperature, and fuel; returns None for empty fleets (prevents division-by-zero and signals emptiness).
- Alerts:
  - Critical Overheating when temperature > CRITICAL_OVERHEAT_TEMP (default 110°C)
  - Low Fuel Warning when fuel < LOW_FUEL_THRESHOLD (default 15%)
  - Alerts logged for observability.
- Configuration: All thresholds and ranges centralized in config.py for easy tuning.
- CLI Reporting: Clear console output with summary, averages, and alerts; graceful messages for missing CSV, empty fleets, or invalid rows.
- Concurrency Simulation (optional): One thread per vehicle updates telemetry periodically; averages/alerts computed using consistent snapshot locking.

4) Implementations & Design Choices
-----------------------------------
- Input Validation: Vehicle converts inputs to integers and enforces allowed ranges; raises ValueError on invalid data.
- Boundary Logic: Alerts use strict comparisons: temperature > threshold, fuel < threshold; exactly at threshold is nominal.
- Thread Safety (concurrency.py):
  - Per-vehicle Lock for writers (updates).
  - Readers (averages/alerts) acquire all vehicle locks in a stable id order to avoid races and deadlocks.
- Centralized Config: Ranges and thresholds live in config.py; single source of truth.
- Decoupled Modules: I/O in io_utils.py; domain in vehicle.py; orchestration in fleet_manager.py; CLI in main.py.
- Backward Compatibility: main.py exposes load_vehicles_from_csv via a shim to preserve existing imports/tests.

5) Usage
--------
- Run with sample CSV:
  python main.py vehicles.csv

- Run tests (unittest):
  python -m unittest -v

- Run concurrency demo:
  python concurrency.py vehicles.csv --iterations 5 --interval 1.0

6) Edge Cases Handled
---------------------
- Empty CSV: Loads zero vehicles; averages print as N/A; summary indicates no vehicles.
- Malformed Rows: Missing fields, non-numeric types, or out-of-range values are logged and skipped.
- Boundary Thresholds: Temperature == 110°C and fuel == 15% do not trigger alerts.
- Missing File: Graceful error and exit code (via main.py); loader raises FileNotFoundError.

7) Performance & Scalability
----------------------------
- Efficient use of comprehensions/generators for averages.
- Concurrency module models I/O-like timing and compares single vs multi-threaded loops (note Python GIL limits CPU-bound speedups).
- For very large datasets, consider pandas.read_csv() or streaming generators and batching.

8) Testing Strategy
-------------------
- Vehicle validation tests (types, ranges, IDs).
- Fleet averages and alerts (normal, thresholds, boundaries, single/empty fleets).
- CSV I/O integration tests (valid/malformed/missing/empty files) using temporary files.
- CLI integration: exit codes and expected stdout.

9) Future Enhancements
----------------------
- Persistence (database) and historical analytics.
- Real-time alerting via webhooks/message queues.
- Additional metrics (battery, oil pressure) with validation and alerting.
- Async ingestion (asyncio) for network-bound telemetry; multiprocessing for CPU-bound analytics.
